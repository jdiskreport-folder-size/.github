# JDiskReport - Charts of Where the Bytes Went

## Read the Chart

The top directory is the question. If it is a user profile, open it and see whether the weight is video, mail, or a virtual machine. If it is Windows, stop and name the subfolder before you delete anything. JDiskReport will show System32 without protecting it. The protection is your decision.

The file-type view answers a different question: one giant disk image versus thousands of small photos. The size histogram shows whether the disk is a few large files. Cleaners that only delete caches will not touch those files, which is correct.

## Views

| View | Tells you |
|---|---|
| Folders | Which directory holds the space |
| File types | Extensions that dominate |
| Size ranges | A few huge files or many small ones |
| Modified time | Old archives versus files from this week |
| Top files | The individual names worth moving |

## Steps

1. Point it at the volume Windows says is full.  
2. Wait until the scan finishes.  
3. Open only the largest folder until you recognize it.  
4. Write down the path.  
5. Move or delete that data in Explorer or with the uninstaller that owns it.  
6. Rescan only if you need the chart to prove the space returned.

## Fits

Someone who wants a chart before choosing a cleaner. A poor fit for SMART health. A poor fit for a dying disk: scanning adds reads. Copy what you can first. A poor fit if you cannot read another user's folders. The chart will omit them or fail on access.

## Requirements

| Item | Expectation |
|---|---|
| PC | A Java runtime the build needs, or the package that includes it |
| Disk | Read permission on the tree |
| Time | Longer on big or slow volumes |
| Action | None inside the chart |

## Limits

Shadow copies, hibernation, and the page file can make the chart smaller than the used-space number in Windows. If the totals disagree, check those before you hunt for a hidden folder. Junctions can double-count. A total larger than the disk is a link, not extra data.

## Fixes

The scan stops on a folder. Permissions, or a huge directory. Run as a user who may read it, or skip that branch.  
Cloud placeholders look small. Only local copies are fully counted.  
You deleted the largest folder and the chart is unchanged. It is a snapshot. Rescan.  
Java will not start. Install the runtime the release asks for, or use a build that bundles it.  
The largest item is Windows. Name the child folder before any delete.

## The Path Leaves with You

A chart is not a task until the path is written down. Zoom until the largest block has a name you recognize, copy that path, and close the report if you want. Delete or move the files in Explorer, or uninstall the suite that owns them. JDiskReport does not need to stay open during the delete. Rescan only when you want the picture to match the new free space.

If the largest block is Windows, name the child folder before you remove anything. Installer caches, old Windows folders, and update leftovers are different jobs from a video library. The file-type view is how you notice one disk image pretending to be a pile of small files. Trust that view when the folder view is too deep to read quickly.

| Largest block | Next tool |
|---|---|
| Videos or mail | Move or archive |
| A cache path | A junk cleaner aimed at that path |
| One ISO or VHD | Decide on that file |
| Windows | Name the subfolder first |
